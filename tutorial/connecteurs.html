05 — Connecteurs

Les briques d'action

Des intégrations prêtes à l'emploi, plus un SDK pour en ajouter sans toucher au cœur du moteur.

💬 Slack read_channel · send_message
✉️ Gmail send_email

🐙 GitHub create_issue
🌐 HTTP GET / POST génériques

Sécurité des credentials

🔐 OAuth2 + PKCE

Vous autorisez un compte via le flow standard Authorization Code + PKCE — Autome ne voit jamais votre mot de passe.

🗄️ Chiffré au repos

Les tokens sont stockés chiffrés en AES-256-GCM. Aucun secret en clair dans la base.

💉 Injection au runtime

Le worker injecte le credential au moment d'exécuter l'action ; il n'apparaît jamais dans le graphe du workflow.

Le flow d'autorisation

# 1. lister les providers disponibles
GET /credentials/providers

# 2. démarrer le flow OAuth (redirige vers le provider)
GET /credentials/:provider/authorize

# 3. le provider renvoie ici, Autome stocke le token chiffré
GET /credentials/:provider/callback

Cœur agnostique : ajouter un connecteur

Le moteur dépend de traits, pas des APIs concrètes. Un nouveau connecteur, c'est implémenter le SDK de connecteur — sans recompiler la logique d'orchestration ni l'éditeur. Les actions apparaissent ensuite dans la palette via le catalogue.

Où c'est dans le code. Les connecteurs vivent dans crates/connectors/ (Slack · Gmail · Notion · GitHub · HTTP + le SDK). Le guide d'ajout est dans docs/CONNECTORS.md.
