01 — Les concepts

Le vocabulaire d'Autome

Quatre notions suffisent à tout comprendre. Tout le reste en découle.

🔗 Workflow

Un graphe orienté (DAG) de nodes reliés par des edges. C'est votre automatisation, décrite en JSON et éditable visuellement. Exemple : « quand un message arrive sur Slack, envoie un email puis archive dans Notion ».

🧩 Node

Une boîte = une étape. Trois familles : trigger qui démarre le flux, action qui fait quelque chose (Slack, Gmail…), logique (if, switch, loop, while).

⚡ Trigger

L'événement qui démarre un run : webhook (HTTP entrant), schedule (cron), polling (interrogation périodique) ou manual (bouton). Chaque trigger pose un run dans la file de messages.

▶️ Run

Une exécution du workflow. Son état (sorties de chaque node, prochain node) est persisté en base à chaque étape : reprise après crash et scaling horizontal gratuits.

Le templating inter-nodes

La clé qui transforme des nodes isolées en un véritable pipeline de données.

Une action peut réutiliser la sortie d'une node précédente avec la syntaxe {{ node_id.champ }}. Le moteur résout ces expressions au runtime, juste avant d'exécuter la node. 

// la node "gmail_send" injecte la sortie de la node "slack_read"
{
  "action_type": "gmail.send_email",
  "params": {
    "to": "ops@example.com",
    "body": "Dernier message #deploys : {{ slack_read.messages.0.text }}"
  }
}
À retenir. {{ slack_read.messages.0.text }} signifie : « prends la node slack_read, son tableau messages, le 1ᵉʳ élément, son champ text ». C'est le même principe que dans n8n / Make.
